# Правила совместной работы

## 1. Ветки и задачи

Основная ветка проекта - `main`.

Формат названия ветки:

`feature/TXX-description`

Пример:

`feature/T07-tests`

Каждое изменение должно быть связано с ID соответствующей задачи.

## 2. Коммиты

Коммиты должны содержать небольшое законченное изменение и понятное описание.

Пример:

`T07: add candidate data validation`

Не допускается добавление паролей, токенов и персональных данных.

## 3. Pull Request

Каждый PR должен содержать:

- цель изменения;
- ID задачи;
- описание выполненной работы;
- способ проверки результата;
- назначенного проверяющего.

Автор PR не может самостоятельно одобрить свой PR.

## 4. Проверка

Перед слиянием другой участник проверяет:

- соответствие задаче;
- корректность результата;
- выполнение критериев готовности;
- необходимые тесты или чек-лист.

После устранения замечаний выполняется повторная проверка.

## 5. Конфликты и ошибки

При конфликте автор согласует изменения с затронутым участником, разрешает конфликт и повторно проходит проверку.

Если после слияния обнаружена ошибка, ответственный участник исправляет её отдельным коммитом или отменяет ошибочное изменение. После этого результат повторно проверяется
